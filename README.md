# 📈 Portfolio Predictor

A single-file, **100% client-side** portfolio dashboard and Monte Carlo forecasting engine. Track your holdings in real time, gauge bubble risk per stock, and project your portfolio 5–30 years into the future using a GPU-accelerated, regime-switching Monte Carlo simulation — all without a backend, account, or data ever leaving your browser.

![Portfolio Predictor](icon.svg)

---

## ✨ Features

- **Live dashboard** — real-time prices, day change, portfolio value, 52-week range bars, analyst consensus ratings, dividends, and portfolio beta.
- **🫧 Bubble Detector** — per-stock bubble-risk score (0–100) blending price percentile, concentration, market sentiment, and beta, with actionable trim suggestions.
- **📊 Monte Carlo Forecast** — Markov regime-switching simulation of up to 20,000 paths across 6 market regimes, rendered as an interactive fan chart with percentile bands and goal-success probability.
- **⚡ Portfolio Weight Optimizer** — searches thousands of allocations using common-random-numbers (CRN) to find weights that maximize your goal probability or median outcome.
- **WebGPU acceleration** — the simulation runs on the GPU via a WGSL compute shader, with an automatic CPU fallback.
- **Multi-currency** — USD, EUR, GBP, CAD, INR with live FX rates.
- **Fear & Greed index**, live market status (pre/open/after/closed), local weather + clock.
- **PWA** — installable, works offline after first load.

## 🏗️ Architecture

Everything lives in a **single `index.html`** (~120 KB) — HTML, CSS, and vanilla JavaScript (no frameworks, no build step). State is stored in `localStorage`; nothing is sent to any server you don't explicitly call.

```
portfolio_predictor/
├── index.html            # The entire app (UI + simulation engine)
├── manifest.json         # PWA manifest
├── sw.js                 # Service worker (offline caching)
├── icon.svg              # Scalable app icon
├── icon-192.png          # PWA icon (192×192)
├── icon-512.png          # PWA icon (512×512)
├── fetch_historical.py   # Optional: download real historical market data
└── data/
    └── market_history.js # Generated by fetch_historical.py (optional)
```

Data flows entirely through public CORS-friendly APIs called directly from the browser (with proxy fallbacks). If the optional `data/market_history.js` file is present, the forecast engine uses historically-calibrated regime parameters; otherwise it falls back to built-in estimates.

## 🧮 Monte Carlo Simulation Math

The forecast models portfolio value over time as a **Markov regime-switching** process. Each simulation path is an independent random walk through market history.

### Regimes

Six market regimes drive monthly returns:

| Regime       | Character                    |
|--------------|------------------------------|
| Bull         | Steady positive drift        |
| Bear         | Sustained decline            |
| Crash        | Sharp, high-volatility drop  |
| Recovery     | Strong rebound               |
| Sideways     | Flat, low drift              |
| Stagflation  | Weak returns, elevated vol   |

Each regime `r` carries a monthly equity mean `μ_r`, standard deviation `σ_r`, and independent bond mean/std. A **6×6 Markov transition matrix** `T[i][j]` governs the probability of moving from regime `i` to `j` each month, and an initial distribution seeds the starting regime.

### Monthly update

For each path and month:

1. Transition regime: `reg ← pick(reg)` using row `T[reg]`.
2. Draw market return: `mkt = μ_reg + σ_reg · z₁`, where `z ~ N(0,1)`.
3. Apply portfolio beta + idiosyncratic term:
   `eq = β · mkt + idioVol · z₂`
4. Draw bond return: `bd = μ_reg^bond + σ_reg^bond · z₃`.
5. Blend by equity allocation `f` and apply cash flows:

```
value ← max( value · (1 + f·eq + (1−f)·bd) + contribution − withdrawal, 0 )
```

Idiosyncratic volatility diversifies away with the number of holdings: `idioVol = 0.025 / √N`.

### PRNG

Randomness uses **xoshiro128++**, with one independent stream per simulation path seeded by a `splitmix32` expansion of the path index. This gives reproducible, high-quality, embarrassingly-parallel random numbers — identical whether run on GPU or CPU. Normal variates are generated via the Box–Muller transform.

### Percentiles

At each month the paths are sorted to extract the 5/10/25/50/75/90/95th percentiles, producing the fan chart. Goal-success probability = fraction of final-month values ≥ your target.

## 🖥️ WebGPU vs CPU

- **WebGPU path** — a WGSL compute shader (`@workgroup_size(64)`) runs one thread per simulation path. Config, seeds, and results are passed via storage buffers; results are read back and reduced on the CPU. This handles tens of thousands of 360-month paths in milliseconds.
- **CPU fallback** — a faithful JavaScript re-implementation of the exact same xoshiro128++ / Box–Muller / regime logic runs when WebGPU is unavailable. Results are statistically equivalent (same algorithm, same seeding scheme).

The badge in the forecast panel shows which engine is active.

## 🫧 Bubble Detector Algorithm

Each holding receives a **bubble score from 0–100**, summed from four components:

| Component            | Formula                                             | Max |
|----------------------|-----------------------------------------------------|-----|
| 52-week percentile   | `(price − low52) / (high52 − low52) × 40`           | 40  |
| Concentration        | `min(weight%, 25)`                                  | 25  |
| Market sentiment     | Fear&Greed → 0 / 5 / 12 / 20 pts                    | 20  |
| Beta amplification   | `min(15, max(0, (beta − 1.0) × 10))`                | 15  |

Fear & Greed buckets: `≤25` Fear → 0 pts, `≤55` Neutral → 5, `≤75` Greed → 12, `>75` Extreme Greed → 20.

### Score labels

| Score  | Label            | Suggestion            |
|--------|------------------|-----------------------|
| 0–25   | 🟢 Fair Value    | —                     |
| 26–50  | 🟡 Elevated      | —                     |
| 51–70  | 🟠 Overheated    | Monitor closely       |
| 71–85  | 🔴 Bubble Risk   | Consider trim         |
| 86–100 | 🚨 Extreme       | Significant trim      |

### Sell-suggestion rules (override the label default)

1. **Concentration** — `weight > 20%` and `score > 50` → *Trim to ~15% weight*.
2. **Peak proximity** — `percentile > 0.90` and `F&G > 70` → *Trim 10–20%*.
3. **High-beta in greed** — `beta > 1.5`, `F&G > 75`, `weight > 10%` → *Hedge*.
4. **Portfolio-wide** — average score `> 60` → banner recommending increased bond allocation.

The panel header shows an aggregate **value-weighted** score (labeled "Wtd") — each holding's score is weighted by its portfolio dollar weight, so a large overheated position drives the portfolio score more than a tiny one. The panel is collapsible.

## ⚡ Portfolio Weight Optimizer

Finds a better allocation without simulating each stock individually. The key insight: for a linear portfolio,

```
R_port = (Σ wₛ · βₛ) · R_market + 0.025·√(Σ wₛ²) · ε
```

so only the **effective beta** `Σ wₛ·βₛ` and **effective idiosyncratic vol** `0.025·√(Σ wₛ²)` matter per allocation.

- **Simplex sampling** — candidate weight vectors are drawn uniformly from the probability simplex via the exponential trick (`wᵢ = −ln(uᵢ)`, then normalize).
- **CRN (Common Random Numbers)** — every candidate is evaluated against the *same* per-path market draws (fixed seeds), so relative ranking is accurate even with only ~200 paths per candidate.
- ~1,000 allocations are searched; the best by your chosen objective (max goal probability or max median) is compared against your current weights.

Because the mini-sim uses few paths, results within ±3% are flagged as statistical noise.

## 🌐 Data Sources

All free, no API key required (except optional Finnhub for richer metrics):

- **Prices** — Yahoo Finance chart API (via `allorigins` / `corsproxy` fallbacks); optional Finnhub quote + WebSocket for real-time trades.
- **Metrics** (beta, 52-week high/low, dividends) — Finnhub (`/stock/metric`).
- **Analyst ratings** — Finnhub (`/stock/recommendation`).
- **Fear & Greed index** — CNN dataviz endpoint (via proxy).
- **FX rates** — open.er-api.com.
- **Weather** — Open-Meteo; reverse geocoding via OpenStreetMap Nominatim.
- **Historical regimes** (optional) — Stooq (S&P 500) + FRED (CPI, 10-yr Treasury, dividend yield) via `fetch_historical.py`.

A free Finnhub API key (from [finnhub.io](https://finnhub.io)) unlocks beta, 52-week range, dividends, ratings, and real-time WebSocket prices. Without it, prices still work via Yahoo and those extra columns show `--`.

## 🚀 How to Run

Because WebGPU and service workers require a secure/served context, open the app through a local web server rather than `file://`:

```bash
cd portfolio_predictor
python3 -m http.server 8000
# then open http://localhost:8000/index.html
```

On first launch you'll be prompted to enter your holdings (ticker + share count) and optionally a Finnhub key. Everything is saved in `localStorage`.

> **Note:** `manifest.json` uses a `/stock_dashboard/` scope. If you serve the app from a different path, adjust `start_url` / `scope` in `manifest.json` to match your deployment (e.g. `./`).

## ⚠️ Limitations & Disclaimers

- **Not financial advice.** All outputs are probabilistic estimates, not predictions. Historical regime statistics do not guarantee future results.
- Returns are assumed approximately Normal within each regime; real markets have fatter tails and stronger cross-asset correlations during crises than the model captures.
- Portfolio beta is a single point estimate (from Finnhub, defaulting to 1.0) and is assumed constant across regimes.
- Idiosyncratic risk is modelled as fully diversifiable (`0.025/√N`), which understates single-stock and sector-concentration risk.
- The bubble detector is a heuristic screen, not a valuation model — a high score is a prompt to investigate, not an automatic sell signal.
- Rebalancing suggested by the optimizer may trigger taxes and transaction costs that are not modelled.
- Third-party data APIs may rate-limit, change, or occasionally return stale/incorrect values.
